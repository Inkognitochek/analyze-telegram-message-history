#  End-to-End Dialogue Analytics Pipeline

Асинхронный ETL-пайплайн для сбора неструктурированных данных из Telegram-диалогов, автоматической транскрибации голосовых сообщений с помощью нейросети Whisper и последующего продуктового анализа паттернов коммуникации.



## 🎯 Бизнес-контекст и цель проекта

В современных продуктовых сервисах (служба поддержки, чаты между клиентом и исполнителем, внутренние B2B-коммуникации) значительная доля входящего потока данных приходится на асинхронные голосовые сообщения. Обработка аудио вручную оператором стоит бизнесу значительно дороже текста и увеличивает время ожидания ответа (SLA).

**Цели проекта:**
1. **ETL / Инженерия данных:** Написать отказоустойчивый конвейер для извлечения сырых сообщений через Telegram API и локальной транскрибации аудио в текст.
2. **Продуктовая аналитика:** Оценить операционные метрики диалога (First Response Time, Voice Share, сессионность) и проверить гипотезу о том, что голосовые сообщения снижают скорость коммуникации.

## 🛠 Стек технологий

* **Сбор и обработка данных:** `Python`, `Telethon` (Telegram MTProto API), `Asyncio`, `ffmpeg`.
* **ML / Speech-to-Text:** `OpenAI Whisper (модель Small)` — локальное распознавание речи на русском языке.
* **Анализ данных:** `Pandas`, `NumPy`.
* **Визуализация:** `Matplotlib`, `Seaborn`.
* **Инфраструктура:** `Google Colab`, безопасное хранение секретов (`google.colab.userdata`).

---

## 🏗 Архитектура пайплайна

1. **Extraction (Сбор данных):** 
   * Асинхронный сбор истории сообщений из чата с фильтрацией по дате (`offset_date`).
   * Реализована защита от лимитов Telegram API (`asyncio.sleep` для предотвращения банов и экспоненциальный retry при `RPCError`).
2. **Audio Processing (STT):**
   * Автоматическая детекция голосовых заметок (`message.voice`).
   * Транскрибация речи моделью Whisper со строгими гиперпараметрами против галлюцинаций модели (`temperature=0.0`, `no_speech_threshold=0.6`).
   * Временные аудиофайлы удаляются сразу после обработки для экономии дискового пространства.
3. **Transformation & Loading:**
   * Структурирование данных в единый датасет (дата, ID отправителя, текст, расшифровка).
   * Экспорт в CSV с защитой от повреждения кодировки (UTF-8).



## 📈 Ключевые метрики и задачи аналитической части

В аналитическом модуле (`analysis`) исследуются следующие продуктовые вопросы:

* **Voice Share (%):** Доля аудиосообщений в общем потоке коммуникации.
* **Response Latency (SLA):** Влияние формата входящего сообщения (текст vs голос) на медианное время ответа собеседника.
* **Sessionization:** Алгоритмическое разбиение потока сообщений на логические диалоговые сессии (по порогу неактивности > 45 минут).
* **Workload Heatmap:** Распределение нагрузки и активности по часам суток и дням недели для поиска пиковых интервалов.
